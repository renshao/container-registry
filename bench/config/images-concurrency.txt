# Corpus for the high-concurrency pull benchmark (bench/concurrency.sh).
#
# 25 public images, ~7.3 GB of linux/amd64 content, deliberately spread across
# three size bands so a single pull size does not define the result:
#
#   8 images    2-120 MB   manifest and small-blob path, high request rate
#  12 images  160-580 MB   the ordinary application image
#   5 images  0.6-2.1 GB   sustained streaming under contention
#
# Mean pull is ~290 MB, median ~180 MB. That ratio matters: with a corpus of
# uniform giants, a concurrency sweep only ever measures the NIC. Here a wave of
# 200 concurrent pulls is a realistic mix, so queueing shows up in the small
# images' latency before the large ones have finished streaming.
#
# Every ref is anonymously pullable and resolves to linux/amd64. populate.sh
# mirrors each one once from its public home, then fans out locally.
#
# The Docker Hub images are named through mirror.gcr.io, Google's pull-through
# cache. Populating 25 images costs well over 25 upstream manifest fetches once
# multi-arch indexes are counted, which trips Hub's 100-per-6h anonymous limit
# partway through the corpus. That surfaces as a failed push into whichever
# engine populate happens to fan out from, so a rate limit reads as a defect in
# the registry under test. The mirror has no such limit and needs no credential.
# Hosts that are not Docker Hub are left pointing at their own registries.
